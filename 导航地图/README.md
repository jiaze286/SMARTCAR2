# 导航地图 —— 赛道中心线（给惯导用）

> 来源：B 车（test16）从 `赛道图-5000x5000-黑底白线.png` 自动提取的赛道中心线。
> 用途：给小车**惯导（里程 + 航向 + 已知几何）**当"已知赛道几何"用：查当前位置、算前瞻、判元素、做地标重置。

## 文件

| 文件 | 说明 |
|---|---|
| `赛道图-原件-5000x5000-黑底白线.png` | **原件**（5m×5m 场地 CAD 图，25mm 白线；含尺寸标注） |
| `赛道中心线-预览.png` | 提取结果叠加在原件上（红线=中心线，绿短线=行进方向），**先看这张确认对不对** |
| `赛道中心线-mm.json` | 路点数据（**10mm** 间隔，全精度；含 s / x / y / yaw / R） |
| `nav_map.h` | 直接 `#include` 的 C 表（**50mm** 间隔，869 点，占 Flash ≈ 17KB） |
| `赛道图转惯导地图.py` | 生成脚本（改间隔/标定/坐标系都能重跑） |

## 坐标系（**必须一致，否则越导越偏**）

```
原点 = 场地左上角（外框左上角）
X    = 向右为正（mm）
Y    = 向下为正（mm，与赛道图同向）
yaw  = 0° 指向 +X；顺时针为正（因为 Y 向下）
R    = 曲率半径 mm；直线段填 1e9
s    = 沿中心线的累计弧长 mm（起点见下）
```

⚠ 如果你的惯导用的是 **Y 向上 / 逆时针为正** 的右手系：把 `y` 取负、`yaw` 取负即可。

## 关键数（都是标定/实测出来的）

| 项 | 值 | 怎么来的 |
|---|---|---|
| 比例 | **5.8005 mm/px** | 场地外框 862px = 5000mm；再用 E 区 R300 圆（外径 625mm=109px）交叉验证 |
| 单圈周长 | **43.43 m** | 沿中心线累计（闭环） |
| 点数 | 10mm 版 4343 点 / 50mm 版 869 点 | 等弧长重采样 |
| 闭环 | **是** | 首尾相接，可循环取点 |

## 怎么用

**固件（C）**
```c
#include "nav_map.h"
/* NAV_MAP[NAV_MAP_N] ：按 s_mm 二分查表；或按 (x,y) 找最近点 */
nav_pt_t p = NAV_MAP[i];
```

**上位机 / 脚本**
```python
import json
m = json.load(open("赛道中心线-mm.json", encoding="utf-8"))
pts = m["pts_mm"]        # [[x_mm, y_mm], ...]
yaw = m["yaw_deg"]       # 逐点航向
R   = m["radius_mm"]     # 逐点曲率半径（直线为 null）
```

## ⚠ 两个必须自己定的东西（图里没有）

1. **s=0 在哪**：自动提取时把**最上最左的骨架点**当起点（在场地的左上角附近），**不是**赛道图上的 S 发车线。要改成以 S 线为 0，就在表里做一次循环移位。
2. **行进方向**：自动提取给的是两个方向中的**一个**（与赛道图同向的绕行方向）。如果实际比赛是反着跑，把整张表**倒序**即可。

## 怎么重生成（改了赛道/换了标定）

```bash
python 赛道图转惯导地图.py  <赛道图.png>  <输出目录>
```
脚本只用 `numpy + PIL`，无需 cv2/scipy。流程：阈值 → 形态学开运算（去标注/文字/外框）→ 取最大连通域（赛道）→ Zhang-Suen 细化 → 带方向行走排序（十字按直行、缺口自动跳、漏走弧补接）→ 标定 → 等弧长重采样 → 出 JSON / C 表 / 预览。

**换赛道**：把新图喂进去、按新图量出"外框像素长度"改脚本里的 `FIELD_PX`，再重跑。

## 已知限制（老实说）

- 是从 **CAD 截图**自动提取的，不是测绘；**弯道处的中心线有 ±2~3mm 量级的抖动**（源自图片像素与细化），对循迹足够，但**别拿它当毫米级基准**。
- E 区 4 个相切圆处，行走器曾在相切点走丢一个圈，已用"漏走补接"补回（现覆盖 100%）；如果以后重跑脚本，**记得看预览图复核**。
- 比赛实际赛道布可能与 CAD 图有偏差（铺装误差），**实跑时用地标（十字/斑马线）重置**来吸收。
