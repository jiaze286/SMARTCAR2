# 调参迭代器 · 使用手册（给人看的） · 2026-10-11

> 配套：`脚本/调参/调参迭代.py`（+ `调参参数.json`）。给 AI 的版本见 `使用手册-调参迭代器-给AI-20261011.md`。
> 本文只讲**你怎么用**，不讲代码怎么改。

---

## 0. 一句话

**它把"改参数 → 烧录 → 跑一圈 → 看结果"这个手工循环，变成"跑一圈 → 自动决定下一组参数"。**
你只要保证三件事：车能跑、固件每圈打一行日志、串口能改参数。剩下的它自己迭代。

**一圈约 8~15 秒；一轮寻优 40 圈 ≈ 8~10 分钟。**

---

## 1. 开始之前：固件必须已经做完这 4 件（**没做完别开始**）

| # | 固件要提供 | 为什么 |
|---|---|---|
| 1 | **参数平铺成一张表**，串口能读能写（`SET 键 值` → 回 `OK`；`GET 键` → 回 `OK 值`） | 脚本靠它改参数 |
| 2 | **每圈结束打印一行 LAP 日志**（格式见 §4） | 没有它，脚本什么都看不见 |
| 3 | `AUTORUN=n`：上电（或收到 `RUN n`）自动跑 n 圈然后停 | 脚本靠它一圈一圈地要数据 |
| 4 | **急停 / 保底**：偏差超限或连续丢线就自己停 | 自动升速是真会甩车的 |

**自检链路通不通**（两条命令，不用上车）：

```bash
python 脚本/调参/调参迭代.py --check          # 环境自检：6 项全 PASS 才算 OK
python 脚本/调参/调参迭代.py --port COM5 --phase A   # 只诊断、不改参数；能看到数据才算链路通
```

---

## 2. 三分钟上手

```bash
# ① 环境自检（不接车）
python 脚本/调参/调参迭代.py --check

# ② 第一次接车：只诊断，一个参数都不改
python 脚本/调参/调参迭代.py --port COM5 --phase A

# ③ 正式跑：诊断 → 压偏差 → 加速，一条龙
python 脚本/调参/调参迭代.py --port COM5 --phase auto

# 只想跑某一段
python 脚本/调参/调参迭代.py --port COM5 --phase B
python 脚本/调参/调参迭代.py --port COM5 --phase C --laps 4
```

**Windows 上先看串口号**（设备管理器 → 端口），别写错 `COM` 号。
**没有 pyserial 也能玩**：`--sim` 用合成模型离线跑，用来确认流程、不当真值。

## 3. 它内部怎么走的（三阶段）

```
A 诊断期 ──► B 压偏差 ──► C 加速
（不改参数）  （单参坐标下降）  （约束偏差下压时间）
```

**A 诊断**：只读日志、不动参数。告诉你偏差是"线偏差为主"还是"惯导横向为主"、是"弯道尖峰"还是"直道持续偏"、往哪边漂 —— 用来决定 B 阶段先动哪个参数。

**B 压偏差**：一次只动**一个**参数，按顺序试 `look_mm → kp_steer → kd_steer → k_gyro → corr_kp → corr_ki`；每个方向 ±3%，**每档跑 2 圈取最差**；有改善还要**复测一次**（同一组再跑一遍，取两次里较差的那次）才接受 —— 这一步是为了不被噪声骗。

**C 加速**：只有**先达标**（合格判定见 §5）才进来。C-1 逐步升 `vmax`（每步 5%），升到不达标就往回退、步长减半再逼近（二分）；**升速只认"更快"**。C-2 再试 `look_mm` / `a_acc`。

**三条保底（自动生效，不用你操心）**
1. **只动白名单键**：电机方向 / 限流 / 引脚映射这类**根本不许动**；
2. **单圈步长 ≤5%**：参数不会一步跳飞；
3. **连续 2 档跑不完 → 回退到"最后一组能跑完的参数"**，并且记住了就不会再往坏方向试。

## 4. 你（或固件）要给它的数据：一行 LAP

固件每圈结束打一行，逗号分隔，**13 个字段，顺序固定**：

```
LAP,圈号,是否跑完,耗时ms,总里程mm,线偏差RMS,线偏差P95,线偏差MAX,惯导横向RMS,惯导横向P95,补偿角均值,脱线次数,结束原因
```

例子：

```
LAP,3,1,8420,13720,1.8,3.9,6.4,2.1,4.8,0.7,0,OK
```

- `是否跑完`：1 = 跑完，0 = 没跑完
- `结束原因`：跑完就写 `OK`；没跑完写原因（如 `LOST` 丢线 / `TIMEOUT` / `ABORT`）
- 单位：mm / mm/s / 毫秒 / 度
- **偏差分两路记**（`线偏差` = 灰度模块给的线位置；`惯导横向` = 惯导点相对路表偏多少）—— 两者混记就没法判断在修谁

---

## 5. 怎么算"合格"和"更好"（写在纸上的判据）

- **合格（闸门）**：跑完 **且** 线偏差P95 ≤ **4.0mm** **且** 惯导横向P95 ≤ **6.0mm** **且** 脱线 = 0
- **分数（越小越好）**：`1.0×线偏差P95 + 0.6×惯导横向P95 + 0.1×单圈秒数`
  （没跑完的档直接给 1000 分，所以"跑完"永远排第一）
- 这三个数字都在 `调参参数.json` 里（`p95_gate_mm` / `ins_p95_gate_mm` / `lost_max` / `w_line` / `w_ins` / `w_time`），**嫌松嫌紧自己改**。

## 6. 三个输出文件怎么读

| 文件 | 看什么 |
|---|---|
| `调参日志.csv` | **每轮一行**。重点看 `decision` 列（含义见下表）和 `note` 列（一句人话解释） |
| `调参收敛.txt` | ASCII 曲线，**条越短越好**；一眼看出哪一轮变好、什么时候回退 |
| `调参参数_best.json` | 最终结果。达标且最快的那组，直接刷进车 |

**`decision` 列速查**

| 标记 | 意思 | 你该做什么 |
|---|---|---|
| `DIAG` | A 阶段诊断 | 读 §3 的诊断结论 |
| `BASE` / `PROBE` / `CONFIRM` | 基准档 / 试探档 / 复测档 | 不用管，过程数据 |
| `ACCEPT` | 接受了这步改动 | — |
| `REVERT` | 改动不够好，保持原值 | 若连续出现，见 §7 |
| `PUSH` / `SLOW` | 升速试探 / 达标但更慢（停在上一档）| — |
| `BISECT` | 连续失败，步长减半（逼近速度上限）| — |
| `ROLLBACK` | **回退到最后一组能跑完的参数** | 说明刚才试坏了，看 `note` |
| `SHORT` | **这一档收不满圈数，作废**（丢帧）| 查串口链路，见 §7 |
| `PUSHFAIL` | **参数没写进去**（写入或回读不过）| 查固件 SET/GET 实现，见 §7 |

## 7. 故障对照表（症状 → 原因 → 怎么办）

| 症状 | 大概率原因 | 怎么办 |
|---|---|---|
| 一条 LAP 都收不到 | 固件没打日志 / 串口不通 / 串口号错 | 先用 `--phase A` 看有没有数据；串口先只插一根 USB（你之前那个"能发不能收"就按交接 3 §0.6 查） |
| 满屏 `SHORT` | **丢帧**（线太长、电机噪声、波特率太高）| 缩短线、降波特率、双绞 GND；`lap_timeout_s` 调大 |
| 满屏 `PUSHFAIL` | 键名对不上 / 固件没实现 SET 或 GET 回读 | 对着 §1 第 1 条逐键试；**没有回读就等于没写进去** |
| B 阶段一直 `REVERT`，note 写"仅改善 x% < 阈 y%" | 要么真到最优附近；要么**阈值高于噪声** | 先**测圈间噪声**：同一组参数连跑 4~6 圈，看 P95 波动多少；波动 >1% 就把 `accept_eps` 调到略高于波动，或把 `lap_per_config` 加到 4~6 |
| C 阶段一直"不达标"、`BISECT` 到很小步长 | 到速度上限了（正常，不是故障）| 接受 `best`；想更快只能改机械/负压 |
| 出现 1000 分 | 有圈没跑完 | 看 `结束原因`：`LOST` = 丢线（降速/加前瞻）、`TIMEOUT` = 卡住 |
| `ROLLBACK` 很频繁 | 步长太大 / 噪声太大 | `max_step_pct` 降到 3%，`accept_eps` 提高 |
| 分数降了但车更慢了 | `w_time` 太小（时间权重不够）| 把 `w_time` 从 0.1 提到 0.2~0.3 |

## 8. 红线（这几条别碰）

1. **不许把电机方向 / 限流 / 引脚映射加进白名单**。那是硬件安全项，自动迭代只配调"手感"。
2. **`max_step_pct` 别调到 >5%**。一次动太多，车是"飞"不是"调"。
3. **车必须留物理急停手段**（开关/断电），并且固件保底先做好。
4. **跑之前**：场地清空、电池充足（电压掉下去偏差会变，噪声也会变大）。
5. **参数只走 `调参参数.json`**，别去改代码里的数字 —— 改了下次就看不懂是哪来的。

---

## 9. 它做不到什么（别期待）

- **不保证全局最优**，只保证"逐圈不倒退"。真车噪声决定了最终停在"最好那次附近"。
- **仿真里收敛 ≠ 参数物理正确**。`--sim` 的真值最优点就是种子值，等于自己出题自己答对，只能用来验证流程。
- **不替代固件保底**。急停、限幅、丢线处理必须在固件里，脚本管不到。

## 10. 名词表（大白话）

| 词 | 意思 |
|---|---|
| **车参** | 直接下发给固件的参数（转向/速度环增益、前瞻、矫正环…） |
| **元参** | 只在本机脚本用的参数（每档几圈、接受阈值、各权重…） |
| **LAP 行** | 固件每圈打完的一行日志（§4） |
| **线偏差** | 灰度模块说"车相对赛道偏了多少" |
| **惯导横向** | 惯导点相对路表偏了多少（虚世界里的偏） |
| **补偿角** | 直道矫正环输出的那个"往哪拧几度"，加到积分航向上 |
| **脱线** | 这一圈线丢了（通常意味着要降速） |
| **闸门 / 达标** | §5 那三个条件全满足 |
| **score** | 一个数，越小越好（偏差 + 时间），用来比较两个配置 |
| **复测确认** | 候选参数再跑一遍，取两次较差的那次再决定收不收 |
| **二分** | 撞到速度上限后，在"能跑"和"跑不了"之间一步步逼近 |
