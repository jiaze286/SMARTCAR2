## 3. 三份契约（改代码不得违反）

### 3.1 参数契约 —— `调参参数.json`

四组，**代码不许写死数值**：

| 组 | 含义 | 示例键 |
|---|---|---|
| `_group_firmware` | 可经 `SET` 下发到固件的**白名单车参**（21 个）| `kp_steer kd_steer k_gyro kp_speed ki_speed kd_speed vmax vmin a_acc a_brake a_lat look_mm corr_kp corr_ki corr_kd corr_enc_k straight_min corner_margin straight_deg corr_on autorun` |
| `_group_fixed` | 建图固定参：**存档用、不下发、不自动改** | `c_long c_lat span_th e_slow` |
| `_group_meta` | 调参元参（只在本机脚本用）| `lap_per_config diag_laps step_b vmax_step accept_eps max_step_pct p95_gate_mm ins_p95_gate_mm lost_max dev_abort_gate_mm lost_streak_abort max_b_sweeps vmax_ceiling vmax_floor vmax_min_step param_lo_factor param_hi_factor w_line w_ins w_time time_tol rollback_after_fail fail_score_penalty force_corr_on max_rounds serial_baud serial_timeout_s lap_timeout_s` |
| `_group_sim` | 合成模型系数（**仅 `--sim`**）| `sim_*` 系列 |

- **白名单是硬边界**：`SafetyGuard.guarded_set` 对不在 `FIRMWARE_KEYS` 的键**直接抛 `RefuseWrite`**。
- `validate_params` 要求 `REQUIRED_KEYS = FIRMWARE + FIXED + META + SIM` 全部存在；**新增元参必须同时进代码的 `META_KEYS` 与 JSON**。
- 边界：`clamp_bounds` 把值钳在 `seed × [param_lo_factor, param_hi_factor]`（0.6~1.6）；`vmax` 另受 `[vmax_floor, vmax_ceiling]`（900~3200）。

### 3.2 遥测契约 —— 每圈一行 LAP（13 字段，顺序固定）

```
LAP,<圈号>,<是否跑完 0|1>,<耗时 ms>,<总里程 mm>,<线偏差 RMS>,<线偏差 P95>,<线偏差 MAX>,<惯导横向 RMS>,<惯导横向 P95>,<补偿角均值 deg>,<脱线次数>,<结束原因>
```

- 解析器 `parse_lap_line`：首字段必须 `LAP`，字段数 `<13` 返回 `None`（整行丢弃）。
- 数值以 `%.6g` 写出 → **精度只有 6 位有效数字**，任何比较都不得用比 1e-5 相对更严的容差。
- `结束原因`：跑完 = `OK`，否则给原因串（`LOST` / `TIMEOUT` / …）。

### 3.3 串口契约

| 命令 | 期望回应 | 备注 |
|---|---|---|
| `SET <键> <值>` | `OK` | **必须支持后续 `GET` 回读**，否则视为未实现（脚本判失败）|
| `GET <键>` | `OK <值>` | 回读值需与写入值相对误差 ≤1e-3 |
| `RUN <n>` | `ACK`（或缺省不回、直接开始打 LAP）| 之后应连打 n 行 LAP |

- 传输层三种实现：`SerialTransport`（实车）/ `SimTransport`（合成）/ `ReplayTransport`（回放 LAP 行）。
- `run(n)` **允许返回少于 n 圈**（丢帧/超时）——调用方必须处理，见 §4。

## 4. 不变量（改代码必须守住）

1. **收不满圈不得下结论**：`eval_config` 在 `len(recs) < laps` 时**再要一次**，仍不满则**判本档作废**（返回 `None`，日志记 `SHORT`、`curve` 记 SHORT），**不更新 `last_good` / `best`**。
2. **参数写不进去不得接着跑**：`push_all` 整组下发，任一键失败先重试一次，仍失败抛 `RefuseWrite`；`eval_config` 捕获后记 `PUSHFAIL` 并返回 `None`；**连续 3 次**抛 `RuntimeError` 停整个流程。
3. **`last_good` 只在 `ev.finished` 时更新**；任何"回退"都回它。
4. **回退后 `self.current = None`**：调用侧必须重新评估（否则会拿失败档的分数继续判据）。
5. **`score` 只对"跑完"的档计算**：未跑完一律 `fail_score_penalty`（1000）。
6. **评分必须含时间项**：`score = w_line·line_p95 + w_ins·ins_p95 + w_time·(time_ms/1000)`；缺了时间项，"加速"就没有度量。
7. **单圈步长 ≤ `max_step_pct`**（0.05）——`SafetyGuard.propose` 里先钳步长再钳边界。
8. **接受判据必须抗噪声**：B 阶段改善**先超 `accept_eps`，再做一次复测**（同配置再跑一档，取两次里**较差**的分数参与判据）。
9. **C-1 只接受"更快"**：达标 **且** `time_ms ≤ t_good·(1+time_tol)` 才继续升 vmax；达标但更慢 ⇒ 记 `SLOW` 停在上档。
10. **C-2 基准档不达标就不做探针**（避免在"已经跑不完"的配置上白烧轮次）。
11. **白名单外的键一律拒绝写入**。

## 5. 运行协议（AI 该怎么操作它）

```bash
python 脚本/调参/调参迭代.py --check                      # ① 环境自检（6 项须全 PASS）
python 脚本/调参/调参迭代.py --port COM5 --phase A        # ② 只诊断：先确认能拿到 LAP
python 脚本/调参/调参迭代.py --port COM5 --phase B        # ③ 压偏差
python 脚本/调参/调参迭代.py --port COM5 --phase C        # ④ 加速（须先达标）
python 脚本/调参/调参迭代.py --port COM5 --phase auto     # 或一条龙 A→B→C
# 离线：--sim（合成，不当真值）/ --replay <文件>（回放 LAP 行复算）
# 其它：--laps n（覆盖每档圈数）/ --max-rounds n / --dry（不写文件）/ --params --log --best --curve 改路径
```

**读结果**：每轮结束看 `调参日志.csv` 的 `decision` 列 + `note` 列；整体看 `调参收敛.txt`（条越短越好）；最终用 `调参参数_best.json`。

**A 阶段输出怎么用**：它会告诉你偏差以"线偏差 / 惯导横向"为主、集中在"弯道尖峰 / 直道持续"、往哪边漂 —— 据此决定 B 阶段先动哪个键（默认顺序 `look_mm → kp_steer → kd_steer → k_gyro → corr_kp → corr_ki`）。

## 6. `decision` 枚举 → 归因 → 允许的动作

| decision | 含义 | 归因 | 允许的动作 |
|---|---|---|---|
| `DIAG` | A 阶段诊断档 | — | 照 §5 用 |
| `BASE` / `PROBE` / `CONFIRM` | 基准 / 试探 / 复测档 | — | 过程数据 |
| `ACCEPT` | 接受改动 | — | — |
| `REVERT` | 改动不够好 | 连续出现 ⇒ 噪声 > 阈值，或真到最优 | 先测圈间噪声再调 `accept_eps` / `lap_per_config` |
| `PUSH` / `SLOW` | 升速试探 / 达标但更慢 | — | — |
| `BISECT` | 连续失败 → 步长减半 | 已接近速度上限 | 正常收敛 |
| `ROLLBACK` | 回退到 `last_good` | 试坏了（偏差超阈 / 连续丢线 / 连续跑不完）| 看 `note`；频繁则降 `max_step_pct` |
| `SHORT` | 收不满圈，本档作废 | **丢帧**（线长 / 噪声 / 波特率 / `lap_timeout_s`）| 修链路；别去改判据 |
| `PUSHFAIL` | 参数没写进去 | 键名不符 / 固件未实现 SET 或 GET | 修固件；连 3 次会自己停 |

## 7. 改代码的规矩与自证清单

**改动前**：交"要动哪几处"清单，等点头（本项目硬纪律）。

**改完必须跑这三项**（缺一不可）：

```bash
python 脚本/调参/调参迭代.py --check            # 6 项全 PASS
python 脚本/调参/调参迭代.py --sim --phase auto  # B 收敛 → C 跑通（含二分）
```

第三个是**两个反例单测**（在 §4 的不变量上做，用假 transport 即可，别写进仓库）：

| 用例 | 构造 | 期望 |
|---|---|---|
| 收不满圈 | 假 transport 首次回 1 圈、之后回 0（请求 2 圈）| `eval_config` 返回 `None`；日志含 `SHORT`；`last_good` / `best_reason` **未被污染** |
| 参数写不进去 | 假 transport `set()` 恒返回 `False` | `eval_config` 返回 `None`；日志含 `PUSHFAIL`；**连续 3 次抛 `RuntimeError`** |

**回归基线（改动不应退化）**：`--sim --phase auto` 应从扰动起点把 score 从 ~9.63 压到 ~7.1（线偏差 P95 4.72→3.48），并让 C-1 把单圈从 ~8390ms 压到 ~7250ms 后撞界二分。

## 8. 已知缺口 / 未验事项（**别假装已解决**）

1. **固件侧 4 件套未做** —— 参数表串口读写 / 每圈 LAP 日志 / `AUTORUN=n` / 急停回退。**没它就没有一条真实数据**，脚本再对也测不出效果。
2. **实车噪声未测** —— 仿真里的噪声是人为设的（线偏差 ~1.5%、惯导 ~2.5%）。实车第一件事就是**同一组参数连跑 4~6 圈量波动**，再定 `accept_eps` 与 `lap_per_config`。
3. **M6（已发现，未改，待用户拍板）**：C 阶段在**临界速度**附近会"达标/不达标"来回翻（日志实证：vmax 3003 不达标 → 2984 不达标 → 2966 达标），二分收敛很慢。两个候选修法：① 升速只接受**有裕度**的档（P95 ≤ 门限×0.9）；② 要求**连续 2 次达标**才认这一档。
4. **`SimTransport` 是玩具模型**（真值最优点 = 种子值）—— `--sim` 的收敛**只证明流程能转**，不证明参数物理正确。
5. **`straight_deg` 在代码白名单里、但契约文档 §2 的表里没有**（键名口径待对齐，属文档侧）。
6. 检查官报告里其余建议项：`best.json` 混着 sim/meta 键（设计如此，重载可直接用）、`kp_steer` 改名（已冻结，不改）。

## 10. 一句话总结

**它能做的**：把"改参数→烧录→跑→看"变成"跑一圈自动决定下一组"，并在无偏差时自动往快里试，同时守住白名单、步长、回退三条保底。
**它不能做的**：替你补固件日志、替你量实车噪声、保证全局最优。
**接实车的前置条件**：§8 第 1 条。
