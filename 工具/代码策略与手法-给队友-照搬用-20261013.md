# 代码策略与手法 · 给队友（可照搬到 C 车 / 任何车）

> **来源**：B 车固件 `bcar`（STM32F103C8T6，机器车循迹）从零做到"阶段 0~6、196 条 PC 单测全过、能上板"过程中的实操沉淀。
> **用途**：C 车（或任何队友的车，**MCU 不限**）可以**直接照搬这套「组织方式 + 纪律 + 台架手法」**；车专属的东西（引脚 / 外设实例 / 传感器 / 参数）按自己的车改（见 §10）。
> **一句话**：**把"能上板一次过"当成唯一目标 —— 用「分层 + 纯逻辑可单测 + 串口台架命令 + 分阶段硬判据」把风险挡在烧板之前。**

---

## 0. 这套策略解决什么问题

新手固件最常见三件事：① 一大坨 `main.c`，改一处崩一片；② 上板才发现引脚/重映射/使能忘配，白耗半天；③ 标定/验证靠"改代码重烧"，试一个参数烧一次。

四条对策：
1. **分层单向依赖** → 改一层不牵连别层；
2. **算法层零硬件依赖 → 在电脑上单测**（B 车有 **196 条**单测，**不接板子、不开 Keil 就能跑**）；
3. **串口台架命令** → 标定/验证变成敲命令，不用重烧；
4. **分阶段 + 每阶段硬判据** → 一步一验，不过不进下一步。

---

## 1. 分层架构（照搬）

```
        app/            决策 + 通信：状态机 / 命令解析 / 参数表 / 遥测
          ↓ 只调
        control/        控制环：速度环 / 转向 / 差速混合 / 减速
          ↓ 只调
        middleware/     ★算法：里程 / 航向 / 灰度定位 / 单圈统计 —— 无硬件依赖，可 PC 单测
          ↓ 只依赖数据结构（不调函数）
        drivers/        外设：电机 / 编码器 / ADC / IMU / 串口 / 蜂鸣 / 按键 / 灯
          ↓ 只调
        bsp/ + HAL      寄存器级底层：时钟 / 引脚 / AFIO 重映射 / SysTick / Flash
```

**三条硬规矩（违反会返工）**
1. `middleware/` **不许 include 任何 HAL/驱动头**——只吃上层传进来的数据结构。这样它才能在电脑上编译（见 §2）。
2. `drivers/` **不许 include middleware/app**——底层不知道上层存在。
3. **ISR 里只搬数据、不跑业务**（`tick++`、进环形缓冲、置标志）；业务全在主循环。ISR 里跑算法 = 时长失控 → 雪崩。

---

## 2. ★手法一：算法层纯逻辑 + PC 单测（最值钱，优先照搬）

**做法**：把"会算错、又难在板上看出来"的逻辑（命令解析 / 里程 / 航向 / 灰度质心 / 分位 / 单圈统计）全放进 `middleware/`，写成**只吃结构体、返回结构体的纯函数**；再配 `Tools/test_*.c` + 一个 `run_pc_tests.py`，用**电脑的 gcc** 编译运行。

**收益**
- 改逻辑**不用上板**，改完 `python Tools/run_pc_tests.py` 几秒出结果；
- B 车实测：196 条单测**抓出过真 bug**——例：`MOTOR FWD 500` 因"先截断命令词"永远解析失败；这种 bug 上板才发现要查半天。

**门槛**：这是整套里**最需要一开始就定好**的（层分错了，后面搬不动）。

---

## 3. ★手法二：串口台架命令（把"标定/验证"变成敲命令）

**做法**：一条 UART（B 车 115200），把每个"要拿尺子/示波器量的东西"做成一条命令，`HELP` 随时可查。
**好处**：现场标定/排故不重烧；**一条命令验一条通路**。

典型命令（照搬"命名即功能"的思路）：
- 链路：`PING` / `STATUS` / `MAPR`（**打印重映射寄存器**，一行定位 AFIO 配没配对）
- 人机：`BEEP` / `LED` / `KEY`
- 执行器：`MOTOR <FWD|REV|BRAKE|COAST> <0~1000>`（只设一侧用 `MOTOR L|R …`）
- 标定：`ZERO`（清零）+ `ENC`（看计数，**推车 1m 标定就看这行**）
- 传感器：`IMU` / `GYROZERO` / `HEAD` / `IR` / `IRBLACK` / `IRWHITE` / `IRPOS`
- 遥测：`TLM 1`（实时行）、`LAP`（结算并打一行）

**要点**：命令解析**放主循环**（不放 ISR）；应答走 **TX DMA**——一条长行阻塞发就是几毫秒 = 几个控制拍。

---

## 4. ★手法三：分阶段落地 + "软件判据 / 硬件判据"分开

**做法**：把固件切成阶段，**每阶段 = 一小块功能 + 一组能判"过/没过"的判据**；判据分两栏：
- **软件判据**（编译 0/0、单测全过）——电脑上就能过；
- **硬件判据**（灯亮、串口收得到、电机转向对）——**必须人在板边**。

**硬规矩**：**任一阶段不过关，不进下一阶段**（防返工最便宜的手段）。

B 车的切法（照搬这个"粒度"）：
```
0 工程/编译/hex/改名（不撞别的车）  1 灯+串口+蜂鸣+按键（打通烧录与遥测）
2 电机开环 PWM                      3 编码器 + 里程（推车标定）
4 IMU + 航向积分                    5 灰度 + 定位
6 光电循迹（先纯光电，好调）         7 惯导为主 + 光电修正（ins_corr）
8 参数表(Flash) + 每圈遥测 LAP       9 接自动调参器
```

## 5. 工具链与工作流（照搬）

| 环节 | 工具 | 说明 |
|---|---|---|
| 编译（不开 IDE） | `"D:\Keil_v5\UV4\UV4.exe" -b xxx.uvprojx -j0 -o build.log` | 再看 `findstr /C:"Error(s)"` |
| PC 单测 | `python Tools\run_pc_tests.py` | 用 gcc；**不要 Keil、不要板子** |
| 烧录 | Keil Download，或 **OpenOCD + ST-LINK** | DAPLink 的 CMSIS-DAP v2 跟 OpenOCD 时通时断，**ST-LINK 稳** |
| 无 Keil 也能干 | `arm-none-eabi-gcc` 裸机工程同样能编 | 应急 / CI 用 |

**每次改完过两道关**：① 编译 **0 error 0 warning**；② 单测**全过**。

**两个"自动化门"脚本（强烈建议照搬）**
- `fix_bom.py`：给中文源码补 **UTF-8 BOM**——中文 Windows 下编译器按 GBK 解析中文会报一堆 warning，破坏"0 warning"判据；
- `patch_uvprojx.py`：CubeMX **重新生成工程后**，把自己 `src/` 的文件**挂回** Keil 工程（CubeMX 只认它自己生成的文件）。

## 6. 五条硬纪律（全是踩出来的）

1. **自己的源码统一放 `src/`，别放工程根**——Windows 不区分大小写，工程根的 `drivers/` 会和 CubeMX 的 `Drivers/`（HAL 库）**撞成同一目录**，重新生成时把驱动全删掉。
2. **改完源码先 `fix_bom.py`**（见 §5）。
3. **CubeMX 重新生成后跑 `patch_uvprojx.py`**（见 §5）。
4. **外设初始化能手写就手写**（重映射 / MOE / 编码器 4 倍频这类，CubeMX 命令行搞不定）；手写还有个好处：意图在明面上，重新生成不会被改回去。
5. **`middleware/` 只放纯逻辑**（§2）；要加可测算法 → 放 `middleware/` 并登记一条单测。

## 7. 已踩坑表（照这份抄能省几天）

| 坑 | 现象 | 解 |
|---|---|---|
| `drivers/` vs `Drivers/` | Windows 大小写撞目录，驱动被 CubeMX 删 | 统一放 `src/` |
| 中文源码没 BOM | 编译器按 GBK 解析 → 一堆 warning | `fix_bom.py` |
| CubeMX 不支持某些重映射 | `IP not ready` 生成失败 | 该外设**手写寄存器** |
| **JTAG 脚复用**（PA15/PB3/PB4 等） | 编码器计数永远是 0 | 初始化第一件事**禁 JTAG 保 SWD** |
| **高级定时器忘开 MOE** | 程序在跑、电机不转（白耗半天） | `__HAL_TIM_MOE_ENABLE`（或 `BDTR.MOE=1`）+ 读回自检 |
| 驱动芯片真值表 `00` | 以为"停"，其实滑行 + **1ms 后休眠** | 控制环里"停"用**刹车态**（`11`），滑行只给测试模式 |
| PWM **消隐时间** | 占空比低于某值（B 车 2.2µs@20kHz≈4.4%）电机不动 | 固件里给占空比设**下限** |
| 长串口输出阻塞 | 一条日志 = 几 ms = 几个控制拍 | 遥测走 **TX DMA** |
| 串口"能发不能收" | TX 通、RX 永远收不到 | ① 引脚**重映射对**（否则 TX/RX 落到不同端口）② **RX 脚配成浮空/上拉输入**（不是 AF_PP）③ 上电打一行 `MAPR` 值 ④ **loopback 自检**（自发收一个字节） |

## 8. 关键设计决定（"惯导为主、光电为辅"怎么落地）

1. **航向靠陀螺积分**（先减零偏、再过死区）；**陀螺只用来"阻尼"，不用来"定角"**，**角度靠积分**——这是"惯导为主"的核心。
2. **光电做位置修正 + 脱线保护**，并做**地标重置**（过十字/斑马线时用已知赛道几何重新对齐航向，治漂移累积）。
3. **打滑会让里程虚高** → 终点/圆环判据必须叠**陀螺角度积分**兜底。
4. **丢线的拍不计入偏差统计**（丢线时 err 恒 0，混进来会把指标做漂亮，而丢线恰恰最危险）。
5. **收敛判据用 P95，不用 MAX**（MAX 被单次反光/震动拉爆，调参器会一直追噪声）。
6. **灰度每路各自归一化**（各探头一致性差，统一阈值必然有的常亮有的常灭）。
7. **误差直接给毫米**（`err_mm`），转向环拿到就能用，不用再标一层系数。
8. **周期用"主循环 + 定时器置标志"**（不在 ISR 跑业务）；超时宁可"跳一拍"（可观测）也不要雪崩。

## 9. 协作工作流（照搬：军师 / 工人 / 检察官）

- **改正式文档走三道门**：① 有实测/出处 ② 用户拍板 ③ 写清出处；攒够**一次性**出，不做增量来回摩擦。
- **先建讨论稿再动手**；**一句话 ≠ 授权**；要改正文先交"**要动哪几处**"清单，等点头。
- **回答风格 = 结论先行 + 厚实质**（每个结论带算术或出处）。
- **接手的标准动作**：先交"**我读到了什么 + 打算怎么动**"，**点头再动代码**。
- **单一入口**：每辆车一个入口文档；**判定哪份是真信息看修改时间**（落款日期不可信）。
- **项目隔离**：各辆车**互不引用**彼此的引脚/参数/文件名（撞名会串车，我们踩过）。
